# Stopped Muse DMA discard

Intent: implement a real bounded digital-buffer discard prerequisite using the already pinned ESP-IDF5.5.4 I2S API, without fabricating native authority or acoustic completion. Exact original Muse lease and checked RX/TX stopped+codec-closed custody are required. Total DMA bytes come from checked TX channel info; require STD, disabled, nonzero4-byte alignment, at most16384bytes. Overwrite all bytes using256-byte zero chunks and exact loaded counts, recheck original custody/state around each call and final info. Only StoppedDmaCleared reports success; unavailable/failed are distinct. Ticket is positive, monotonic per binding, consumed before the first driver call, never silently retried. Revoked-but-held cleanup is permitted, never renews rights. A reentrant discard/open/release must not interleave with this operation. No actual audio samples, new runtime route/permission or constructor IO.

Approaches: DMA-sent fence is insufficient for discard; legacy i2s_zero_dma_buffer is incompatible with the pinned new channel driver. Reuse i2s_channel_get_info + disabled-channel preload, with checked current geometry and bounded call count. This is our implementation choice under Mike's explicit source-continuation direction. Keep CoreVoiceCodec::FlushOutput false, NativeUnavailablePermit false and no live registration. Digital stopped/DMA-cleared source evidence is not acoustic silence, vendor-internal erasure, real hardware or native consent proof. No flash/live/credentials/security actions. Stock/Mira/USB behavior and layout/trust unchanged; API guarded Muse&&voice.
