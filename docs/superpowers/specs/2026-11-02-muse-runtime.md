# Serialized Muse device voice owner

Build the next source prerequisite to actual device voice: one stable serialized runtime owner composing the existing Admission, RAM reader, DeviceVoiceConsent, VoiceSessionOwner and DeviceVoiceReviewUi. It transfers only an unused exact Protocol/Clock/reader admission, keeps permission and widget alive through original checked cleanup, drives bounded SDK ticks and review after returned-target admission, and consumes widget prepare/end intents on its owner loop. It offers explicit playback only after reviewed directions bind; no microphone hold/capture interface or physical flush claim. No constructor IO or automatic launcher/route/task registration.

Executor choice: reuse actual SDK/Core/retained owner/widget, not duplicate their state machines or spawn concurrent UI/audio workers. Ports and original callback contexts are borrowed through cleanup, parent LVGL object through UI Close, all calls serialized under the LVGL owner lock. Close/end during any callout latch and revoke immediately; never destroy executing state. Failed stops/joins or callbacks retain the same original objects. No renewal/reopen/account/target substitution, and no callback-based fake join. End confirmation comes only from the validated SDK reply. Hidden review may be shown again for the identical session; closing review ends it. No silent retry of uncertain network operations.

A quiet source constructor and explicit authenticated-scope Open are not live authority or a registered phone/device entry. Original voice/network/credential scope remains independently required before SDK admission. Native Hold, physical FlushOutput, capture/play observations and full hardware/provider/recovery acceptance stay unavailable. No real credentials, endpoints, device/USB/reset/flash/security changes, paid services or merge. Source PR publication authorized; user handles merges.
