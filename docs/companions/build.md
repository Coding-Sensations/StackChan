# Source qualification and build

`firmware/CMakePresets.json` defines `muse-ram-reference`: five named companions plus Stock, Music/Games excluded, Muse credentials RAM-only, local portraits off. Bounded motion is independently selectable before flashing and stays off in this preset; it has no automatic startup caller. No profile grants native permissions or creates a transport.

Fetch the pinned public source dependencies using the existing repository workflow, then build with the ESP-IDF environment and `cmake --preset muse-ram-reference -S firmware` (or the equivalent cache values). Supply only separately approved local trust/binding inputs through the existing generator when enabling remembered companion boot. Never commit local config, credentials, keys, SDK tokens or portrait payloads. Default/public CI configuration is a source build, not the private locally qualified device image; byte identity is not claimed across these configurations.

Firmware host checks: prepare the existing exact host fixture dependencies, configure `firmware/tests`, build with assertions enabled and run CTest with no skipped tests. The new declaration-only cJSON header is byte-pinned to the qualified SDK source with its MIT license; the UI fixture does not import a library binary. `CMAKE_COMMAND` and `NINJA_COMMAND` can select existing tools; otherwise PATH is used.

Standalone companion checks: install only the hash-pinned hosted-test dependencies in an isolated environment, then run `python scripts/ci/test_companion_routes.py`. It runs the actual HTTPS/parser/deadline, typed-tool, repeated-turn and signed event/room code with controlled last-mile ports and forbids real socket connects. Actual installed MCP2.3 schema/handler compatibility was separately qualified locally without a server/listener; CI's source tests are not that SDK qualification.

The existing PR workflow uses disposable standard GitHub-hosted runners, read-only repository permissions and pinned actions/container. No private runner, PR-target trigger, deployment, credentials, manual duplicate run or paid service is added. ESP32-S3 CI selects the RAM-only no-Music/no-Games source profile; it does not flash hardware. Runtime native ownership, live credentials, capture/output, physical stop/rearm, exact chat/context and recovery boot require separate acceptance.

The two macOS CI jobs use `macos-15-intel`, a [standard free public-repository runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). The prior `macos-15` ARM64 pool twice abandoned both jobs before assigning any runner or executing a step. The jobs retain every existing compile command and offline model assertion, pinned checkout, read-only permissions and strict aggregate dependency; no larger/paid runner is selected. Their source inputs contain no required ARM-only assertion or prebuilt architecture-specific library.

This is native Intel compilation/model execution, not ARM64 execution coverage. The unsigned app is compile-only and is not distributed or launched. ARM64 application/runtime, native audio/camera/device ownership, heap/stress and live-provider acceptance remain separate unmet gates. This runner selection does not turn any of those into passed checks or grant a permission.

## Muse CoreS3 hardware boundary

The guarded CoreS3 Muse API binds the caller's original `CommonAudioAuthority` Muse/MusePushToTalk lease. It does not acquire a DirectUsb lease, issue permission, register a live voice route or start hardware on acquisition. Public USB and generic codec entrypoints cannot use that binding. Raw reads/writes are bounded to 2,048 samples at the board's 24 kHz rate (reference-enabled input is interleaved two-channel); The PCM adapter below supplies conversion; native owner composition and packetization are still required before connecting it to the Muse voice protocol.

Cleanup requires separate successful I2S stop and codec-close receipts for each direction, including directions never opened. A failed close retains custody. Checked hardware release does not release the original logical lease; its owner must join its workers and release that lease. The legacy codec guard stays in place until then. Revocation permits cleanup but no further live IO. The generation-bound DMA ticket reports digital transmission only, never acoustic completion or permission to use the speaker. Enabled flags are not actual recording/playback evidence.

The `muse_codec_test` CTest fixture compiles the production CoreS3 method bodies and actual class declaration with inert driver doubles, real lease authority and real DMA fence, under ASan/UBSan. It checks ownership, foreign/stale leases, partial-open/disable/close failures, revocation during IO, retirement ordering, and Stock/Mira/USB regression. Header and target syntax checks cover Muse/voice on and parked closures. These checks do not qualify physical audio, heap/stress, device recovery or a live session.

## Muse PCM conversion adapter

`muse_voice_pcm.hpp` uses the existing ESP AE sample-rate converter already used by Mira and direct USB; no new DSP implementation/library is imported. It borrows the exact Muse lease and the checked CoreS3 port from PR21. Preparation only allocates selected DSP handles. It never acquires/releases custody, enables/stops a direction, registers a voice route or grants native permission. All methods must run serialized on the retained session worker; close the DSP before releasing logical custody. Reusing a closed adapter requires a fresh common-lease generation.

Capture reads 480 frames at 24 kHz, selects microphone channel 0 rather than reference channel 1, and returns the converter's actual 16 kHz count into 512-sample caller storage. Playback accepts 1–320 mono 16 kHz samples per call, converts into bounded 768-sample raw output and uses checked CoreS3 writes. Successful zero output during filter startup is preserved, not padded into invented audio; the future session worker must packetize/carry actual capture counts and split playback chunks. Every callout rechecks original current custody; failure revokes it and requires owner cleanup, without replaying a possibly completed write. All owned scratch extents are wiped, including tails beyond a converter's reported output count. Fixed sample scratch is 5,056 bytes (3,456 bytes of vector storage plus 1,600 bytes in arrays), in addition to object bookkeeping and vendor DSP allocations. Runtime heap margin and erasure of the vendor converter's internal allocation are not established by these fixtures.

Tests exercise production adapter control/length/wipe behavior against inert DSP and codec ports, and target syntax instantiates it with the real CoreS3 type and ESP declarations. They do not execute the ESP DSP library or establish numerical response, acoustic quality, runtime heap/stress or physical audio. No native observation/permission/session worker is substituted.
