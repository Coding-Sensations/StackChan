# Muse voice service exchange

`voice/service_exchange.*` closes the wire-framing gap between the retained portable `Protocol` and the pinned SDK `ClientSession`. `stackchan_muse_voice_exchange_api()` exposes a dormant version-1 table for an owner-managed, aligned heap allocation. The existing protocol API remains version 2. The voice build profile includes both exchange units and their link root; Muse-off or voice-off excludes them. Construction creates no socket, task, token, codec or permission.

## Native owner contract

The future native owner must supply an exclusively borrowed, already-established and endpoint-verified Noise session, plus the matching protocol. `isEstablished()` is only an SDK handshake state; it is not trusted actor, provider, admission or receiver evidence. The actual session must not be shared with text/link-control traffic or reused by another generation. The owner must enforce current admission and original-owner cleanup authority, clocks, deadlines, serialization and physical port incarnation outside this data/framing adapter. Audio still requires independent native microphone/output permits; the existing unavailable permit stays false. No new live route or startup caller is registered.

Call `Begin` with the exact captured scope, then `Queue` for each pending protocol operation. The exchange uses the SDK's real application-request, body-chunk and reset encoders. Media uses `application/x-ndjson; charset=utf-8` and stays open; end-call uses JSON and closes its request body. Request/envelope storage remains stable until the SDK has produced all payloads and each has a full successful native write acknowledgement.

`Next` returns one borrowed payload and a nonzero ticket. It must be fully sent on the original transport and acknowledged through `Written(ticket, true, now)` before another is obtained. Tickets belong to this exact retained exchange instance: callbacks must capture that instance and never be redirected to a replacement allocation/session even if numeric IDs match. Stale/duplicate tickets cannot acknowledge or revoke a newer payload. Partial, failed or uncertain sends call `Written(..., false, ...)` or `Abort`; they cannot be retried. `Next` advances the SDK transport nonce, so even an unsent payload must not be regenerated.

`Receive` returns `Consumed`, `Busy` or `Failed`. Busy means no inbound bytes or receive nonce were consumed: retain the same bytes, drain the outbound operation, then retry them. The owner must not drop Busy bytes or read another frame over them. Failed requires `NeedsTransportClose` inspection/physical cleanup; malformed data and wrong/duplicate stream headers fail closed. SDK split-message reassembly persists until a complete frame. Media input is bounded by the existing NDJSON protocol limit; end-call response chunks share a 512-byte budget and require one preceding successful response head. Response/body/reset correlation is exact to the captured media/end streams.

Valid parsed terminal events retain the SDK's end-call/half-close cleanup sequence. They are not parse/transport failures. The protocol stops consuming later media bytes after entering Ending; malformed NDJSON still fails closed. A failed/uncertain transport uses the explicit `Protocol::TransportFailed` transition, wiping protocol operations/media and requiring actual close/join. It never fabricates end-call success.

The retained native owner must stop/join the real socket and callbacks, destroy the borrowed session without further use, then call `Joined(true)` on the still-live exchange storage. `Joined(false)` never releases storage. The native boolean is a private owner result, not an authenticated receipt and not an argument an untrusted producer may supply. The factory refuses destruction while bound. Once joined, owned request, frame, reassembly, playback-related transport and response buffers are wiped; protocol destruction remains the protocol owner's separate responsibility. An end-call ACK, media EOF, default destructor or local receipt is not proof of join or resource release.

## Retained native session worker

`firmware/main/companion/muse_voice_session_worker.hpp` composes the actual SDK exchange with the existing NoiseSocket-shaped port, Clock/Custody interfaces and returned-target review bridge. `Adopt` transfers exclusive original session/socket pointers only on success, without connecting, sending or reading. The crypto backend, Protocol, Clock and Custody must outlive this retained worker. Native admission and exact provider/VM/device binding remain the supplying owner's responsibility; an established Noise session or local budget is not that proof. No live-capable route is registered.

The worker is heap-allocated through its checked factory; its large fixed exchange/frame storage must not be put on a small task stack. A native owner must serialize Tick, Cancel, Close and all review/UI access on its retained worker, and drain UI references/callbacks before destroying it. The socket must retain no caller buffer after Send/Receive returns, as required by the existing NoiseSocket contract. This is a bounded loop driver, not an automatically created FreeRTOS task.

Begin pins the exact generation and both budget expiries. Tick polls protocol deadlines even without input, and performs at most one write and one read with bounded remaining-budget timeouts. Original budget/currentness is rechecked after timestamp and endpoint callouts and around every IO. Busy input is retained unchanged before any further read. A full native write is acknowledged once; failed, partial or uncertain sends retire the session rather than replaying a nonce-advanced payload. Native callbacks can request cancellation/close while busy but cannot destroy or reenter the active session.

Voluntary Cancel preserves the SDK end-call sequence while original admission remains current; expired/revoked authority cannot authorize a cleanup send. Errors, expiry or stop retain custody and demand explicit Close. A failed original-socket CloseAndJoin keeps the SDK session, protocol and exchange alive. Only a successful native close/join retires the original SDK session, then releases exchange storage. The destructor performs no network operation and asserts checked cleanup completed. A local join boolean is a private native-owner result, not a transferable authenticated receipt.

The existing review bridge projects the returned session/thread and maintains its local receipt. Its NativePermit remains false: reviewing that screen does not enable audio. The actual admitted startup path, native microphone/output permission and observations, PCM packetization/carry and physical interruption/flush receipts still require integration. No SDK token, pairing, hardware operation, capture/output or alternate provider route is added here.

Host tests link the actual SDK/session/framer/exchange and shared encoded-server fixture, using the existing pinned test-only nonce-tag crypto and inert socket/clock/custody. They cover returned-target review, multi-frame reassembly, protocol-only repeated microphone append framing, graceful cancellation/late media, clock/budget/endpoint changes, callout revoke/remap, reentrant cancellation, no write retry and retained uncertain join. Injected protocol samples and local review receipts are not native microphone, physical flush, actual cryptography or live-provider evidence. The existing exchange assertions, including the human/Copilot shutdown regression, remain intact after extracting their common Server helper.

## Scoped native admission composition

`muse_voice_admission.hpp` reuses DeviceCredentialReader, exact VM lookup, the SDK Noise handshake and retained session worker. `muse_voice_admission_native.hpp` supplies the concrete NativeVmLookup and DirectMetaSocket constructor factories. Creation performs no network/credential IO; no startup caller, route, enrollment, task, microphone/output permission or new storage backend is registered. Both ports are separate from the text session.

A captured scope contains node, VM, call and the exact generation/monotonic/wall expiry budget, with independent original-scope credential, network and voice-admission checks. Existing Clock/Custody must remain current around every phase. Voice admission permits protocol setup only; it is not microphone/speaker consent or authenticated principal evidence. The source owner must supply real authority for the exact actor, account, selected node/VM and generation. Default missing/revoked callbacks fail before a credential read. Protocol's pure shared ID validator rejects unsupported node/call characters, including embedded NULs, before any credential/network call. The SDK admission JSON formatter is not used as an identity validator.

The existing reader loads only the exact node. Refresh is cleared before lookup; the access record clears immediately after exact VM lookup. Lookup must join successfully before connection/handshake. The VM bearer clears immediately after ConnectMeta, before any Noise message. RAII Secret buffers also wipe every failure exit. No access/refresh/bearer value is copied into an admission-owner or worker member, printed, logged, enrolled or written to storage. The caller’s separately authorized RAM credential custody is not silently erased or changed. The caller explicitly chooses and retains its authorized DeviceCredentialReader; this code does not choose NVS or change the RAM-only reference profile.

Handshake writes use the original verified Meta socket with currentness and remaining-budget checks around each call; uncertain writes are never retried. The established session and original socket are adopted by the retained worker without sharing/replacing text state. API/DNS lookup and socket close/join are checked separately. A failed Open or uncertain join retains the owner, ports and callback context until explicit Close completes. Lookup callbacks retain no caller credential record after FindExactVm returns, and sockets retain no caller bearer/frame buffer after their call returns, matching the existing native implementations.

Asserted destruction is a caller precondition, not a cleanup mechanism: retain this admission owner, crypto backend, Protocol, reader, Clock/Custody and UI context through successful Close, including failed Open. Close revokes but preserves the closed review bridge until owner destruction, allowing the caller to drain UI references afterward; all worker/UI access must remain serialized, and callbacks must be drained before destruction. The admission handshake buffer is bounded to 512 bytes, matching the existing incoming limit; outgoing empty-payload Noise messages are checked against SDK size constants. The factory keeps the retained worker’s large storage on the heap. Actual heap margin/stress remains unqualified.

The host fixture executes the actual SDK handshake/exchange/worker with synthetic credentials and inert lookup/socket/clock/custody. It checks exact node/VM refusals, pre-read scope/ID failures, secret clearing between phases, uncertain lookup/socket joins, callout revocation/reentrant close, returned review lifetime and no retry. Test-only nonce-tag crypto is the existing attributed fixture, not cryptographic verification. Native target syntax checks use the concrete existing backends. Genuine native approval/entitlement/receiver evidence, actual remote voice admission, audio composition/packetization/flush/observation, resource stress and device/recovery/live acceptance remain unmet.

## Native codec and frame composition

`muse_voice_core_codec.hpp` binds the direction Owner to the existing CoreS3 API and PCM adapter with its exact opaque original audio lease. The native type alias/constructor is in `muse_voice_core_codec_native.hpp`. Generation-only Reserve has no native fallback. ReserveExact requires the original Muse/MusePushToTalk resource, selected directions, bounded expiry, the Owner's existing fresh Clock and an operation gate built from its existing Permit/context/hold ticket. No permit, principal, route, worker task or physical authority is created. NativeUnavailablePermit and the unregistered startup path remain unchanged.

The guard proxy samples Clock and rechecks the captured gate before/after every physical read/write, including between bounded playback chunks. Owner guards also use fresh time after blocking calls, before protocol append. Resource callback replacement cannot authorize a stale lease or revoke its successor. This source assumes bounded existing permission/clock ports and serialized execution; original actor/receiver evidence is still required outside this adapter.

Capture retains converter-returned samples in an 832-sample buffer and emits 320-sample 16 kHz frames in order, with at most one 480-frame physical read per call. Legal startup/short output returns Pending rather than fabricated data or fatal stop. Playback of at most 1282 samples is split into at most five 320-sample conversions/writes. An uncertain/partial write revokes and cancels; it cannot be replayed. Owned carry/scratch is wiped on stop/error, and selected DSP history is reset without renewing revoked rights. Vendor-internal erasure and actual DSP numeric/audio response remain unqualified.

A successful binding owns digital cleanup obligations too. Owner stop checks both Core directions, including paired TX and never-opened bindings, then joins synchronous codec work and retires hardware before releasing the original logical lease. Every failed/unknown stop retains custody. Codec Join proves only that this serialized codec owns no pending calls/tasks; transport/UI/session workers retain separate joins. Checked open/closed observations never assert actual capturing, playing or acoustic completion.

Physical playback flush is intentionally unavailable: software reset, queue clearing, codec-close or DMA-sent evidence cannot manufacture a discard/flush receipt. The native backend returns false, so a PTT transition requiring flush stops before microphone IO. A narrowly labeled synthetic flush boundary in host tests exercises Owner/control/frame behavior; it is not supplied by production and establishes no hardware evidence. Completing actual physical flush/stop/observation and native permissions remains necessary before live registration.

Tests compile production Core methods/header, real resource authority, PCM adapter and voice protocol/Owner against inert ESP IO/DSP faults; they do not replace those state machines. Existing Core assertions remain, with a shared fixture used to avoid copied production logic. Real target syntax instantiates the native types. No actual microphone, speaker, token, endpoint or device is used.

## Stopped DMA discard prerequisite

`CoreS3AudioCodec::MuseDiscardOutputChecked(original_lease, ticket)` is a separate digital operation. It requires the exact held Muse/MusePushToTalk binding and both checked RX/TX stopped and codec-closed receipts, including the paired TX clock case. It accepts a revoked-but-still-held lease for cleanup; success never renews current rights. A positive monotonically increasing request ticket is consumed before any driver call, including failed attempts. Reentrant discard, enable or hardware release cannot interleave. No route or existing caller invokes this new primitive automatically.

It reuses [ESP-IDF5.5.4 channel-info/preload APIs](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-reference/peripherals/i2s.html). The qualified local SDK is commit `735507283d5b2f9fb363a1901172dbd9e847945d`: `i2s_channel_disable` resets the preload descriptor cursor, and `i2s_channel_preload_data` can fill the disabled channel starting at descriptor0. Current TX STD geometry must be disabled, nonzero,4-byte aligned and at most16,384bytes. Every reported DMA byte is overwritten with zero in chunks of at most256bytes (at most64calls), checking exact loaded counts and retained original stopped custody around each call and rechecking geometry afterward. An enabled-channel observation invalidates the cached TX stopped receipt, requiring a fresh checked stop during cleanup. Calls have a bounded count, not a claimed timeout over the underlying driver mutex. No vendor source is copied or changed.

`StoppedDmaCleared` means only that the pinned driver accepted an exact overwrite of all its reported stopped TX DMA bytes. Error/short load/geometry drift returns Failed, revokes the original scope and never silently retries. Wrong/stale scope, unavailable stopped state and repeated tickets return Unavailable without IO. A fresh checked TX disable is required for another full overwrite: without it the full preload cursor causes a short result and failure, rather than a fabricated success. Remaining checked stop/close and logical owner cleanup still belong to the caller.

This is not DMA-sent, acoustic completion, amplifier/codec-internal erasure, new microphone/speaker authority or a playback-flush acknowledgement. CoreVoiceCodec::FlushOutput and NativeUnavailablePermit remain false; live registration, native authority, physical flush/observations and actual device/heap/provider acceptance remain separate unmet gates. Host tests execute the actual production Core methods against inert driver faults; real target checks compile the pinned APIs. No device, audio or credential use is included.

## Retained audio, admission and UI lifetime

`VoiceSessionOwner<Admission>` transfers an unused admission only when its Protocol and Clock are the exact original instances. The stable heap owner borrows those ports, the existing codec/native authority and original scope callback contexts through complete cleanup. The typed native constructor uses the existing native admission/Noise/Core backends; construction has no credential, network or hardware IO and registers no route. Callers must not independently drive transferred admission or borrowed protocol/codec ports during ownership.

Explicit Open wraps the original credential/network/voice scope checks; close/end requests during callbacks invalidate the in-flight phase before its next authorized operation. There is no reconnect, second Open or uncertain write retry. After SDK admission returns a live target, a bounded move-only ReviewBorrow exposes the actual Bridge for the existing review dialog. Before that, no Bridge is exposed that could permanently revoke itself by opening an incomplete target. Reviewed directions use the actual PR28 owner and independently supplied native authority; local review remains data only.

Close immediately revokes direction and review use, then completes actual audio stop/join/release before calling original admission CloseAndJoin. Failed audio cleanup prevents transport retirement. Failed transport join retains the original SDK/socket. Admission Tick also refuses recursive authority-check entry; Cancel/Close request stop but defer mutation while the original CurrentGrant callback is executing. This protects scope closure lifetime even when review access occurs outside the session operation guard. Even after transport join, admission/review objects remain alive until every original UI borrow is released; only then does final destruction occur. At most eight borrows exist. Moves preserve counts; handle release performs no IO and cannot claim transport completion. Borrow Get becomes unavailable on end/close, but the backing Bridge remains alive through the outstanding handle lifetime. UI owners must serialize/drain their own callbacks and stop retaining raw references before resetting handles. This is a lifetime protocol, not evidence that a registered native LVGL owner has drained callbacks. Destructor requires complete cleanup and zero borrows; it performs no substitute hardware/transport teardown.

End stops audio first and queues the existing worker's cancellation once under its original still-current scope and remaining budget. Only ending transport ticks continue; direction methods cannot resume. In-flight or uncertain cancellation may fall back to closure. A local stop/send never sets EndConfirmed: that value comes only from the actual protocol's validated remote end reply. Clock loss or authorization expiry cannot prevent cleanup of already-held original resources. Normal empty/not-held/pending results from an otherwise Ready direction owner do not themselves force closure. CloseRequested, EndRequested and DirectionsBound are lifecycle/resource state only, not capture/playback or connection-quality observations.

Tests compose the actual SDK/Noise session/framer/protocol/admission/returned review/retained direction/Core/PCM source with synthetic credentials, native matching and inert IO. They exercise audio-before-transport ordering, failed joins, UI reference retention and moves/limits, reentrant end/close, missing grants before reads, no replay, clock-loss/provider-exit cleanup, physical-flush refusal and end acknowledgement. Existing admission/permit/Core assertions remain after sharing fixture setup. No real token, endpoint or device is used; test-only nonce crypto is not cryptographic verification.

The retained-session slice alone does not implement a device launcher or native issuer.
