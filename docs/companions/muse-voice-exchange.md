# Muse voice service exchange

`voice/service_exchange.*` closes the wire-framing gap between the retained portable `Protocol` and the pinned SDK `ClientSession`. `stackchan_muse_voice_exchange_api()` exposes a dormant version-1 table for an owner-managed, aligned heap allocation. The existing protocol API remains version 2. The voice build profile includes both exchange units and their link root; Muse-off or voice-off excludes them. Construction creates no socket, task, token, codec or permission.

## Native owner contract

The future native owner must supply an exclusively borrowed, already-established and endpoint-verified Noise session, plus the matching protocol. `isEstablished()` is only an SDK handshake state; it is not trusted actor, provider, admission or receiver evidence. The actual session must not be shared with text/link-control traffic or reused by another generation. The owner must enforce current admission and original-owner cleanup authority, clocks, deadlines, serialization and physical port incarnation outside this data/framing adapter. Audio still requires independent native microphone/output permits; the existing unavailable permit stays false. No new live route or startup caller is registered.

Call `Begin` with the exact captured scope, then `Queue` for each pending protocol operation. The exchange uses the SDK's real application-request, body-chunk and reset encoders. Media uses `application/x-ndjson; charset=utf-8` and stays open; end-call uses JSON and closes its request body. Request/envelope storage remains stable until the SDK has produced all payloads and each has a full successful native write acknowledgement.

`Next` returns one borrowed payload and a nonzero ticket. It must be fully sent on the original transport and acknowledged through `Written(ticket, true, now)` before another is obtained. Tickets belong to this exact retained exchange instance: callbacks must capture that instance and never be redirected to a replacement allocation/session even if numeric IDs match. Stale/duplicate tickets cannot acknowledge or revoke a newer payload. Partial, failed or uncertain sends call `Written(..., false, ...)` or `Abort`; they cannot be retried. `Next` advances the SDK transport nonce, so even an unsent payload must not be regenerated.

`Receive` returns `Consumed`, `Busy` or `Failed`. Busy means no inbound bytes or receive nonce were consumed: retain the same bytes, drain the outbound operation, then retry them. The owner must not drop Busy bytes or read another frame over them. Failed requires `NeedsTransportClose` inspection/physical cleanup; malformed data and wrong/duplicate stream headers fail closed. SDK split-message reassembly persists until a complete frame. Media input is bounded by the existing NDJSON protocol limit; end-call response chunks share a 512-byte budget and require one preceding successful response head. Response/body/reset correlation is exact to the captured media/end streams.

Valid parsed terminal events retain the SDK's end-call/half-close cleanup sequence. They are not parse/transport failures. The protocol stops consuming later media bytes after entering Ending; malformed NDJSON still fails closed. A failed/uncertain transport uses the explicit `Protocol::TransportFailed` transition, wiping protocol operations/media and requiring actual close/join. It never fabricates end-call success.

The retained native owner must stop/join the real socket and callbacks, destroy the borrowed session without further use, then call `Joined(true)` on the still-live exchange storage. `Joined(false)` never releases storage. The native boolean is a private owner result, not an authenticated receipt and not an argument an untrusted producer may supply. The factory refuses destruction while bound. Once joined, owned request, frame, reassembly, playback-related transport and response buffers are wiped; protocol destruction remains the protocol owner's separate responsibility. An end-call ACK, media EOF, default destructor or local receipt is not proof of join or resource release.

## Registered native held input and guarded PTT composition

`NativePointerHold` is owned by the retained runtime and borrowed by its exact local consent/UI. Only the actual review widget can mint its increasing ticket, on the registered pointer's native press over the visible original Hold button. Every Hold permit checks the same reviewed generation, current microphone consent/context and the real pointer's pressed state and point inside that button under the original checked LVGL lock. Ticket metadata alone, a timer, programmatic click or caller-supplied boolean cannot authorize a read. Foreign/replaced input, loss/release, moving outside, render/Return/Close, clock/context/provider/credential loss or lock failure cancels use; a failed query cannot revive when input returns. Atomic revocation may arrive during an already executing read; it prevents subsequent authorized IO/PCM append but does not retrospectively erase acquired audio or attest physical latency.

The queued native UI callback issues/cancels only the private input ticket; no SDK, Clock or codec IO runs there. The protocol owner handles an ordinary release before its next audio tick, requests the original session's hold/release and performs at most one existing bounded capture per poll. Release during SDK/codec IO may force checked session teardown rather than continuation. Failed original stop/join retains audio/transport/UI custody; neither a button release nor the ticket is a cleanup receipt. No automatic playback is added, and microphone/output consent remains independent.

**Production PTT remains disabled.** Every protocol Hold requires playback-flush acknowledgement. `Codec::SupportsNativePtt()` is a default-false availability prerequisite, separate from input and permission checks; the real Core adapter inherits false because its `FlushOutput` cannot prove physical discard. There is no configuration flag to replace that proof. Native review therefore displays the physical-flush limitation and exposes no Hold control. Digital stopped-DMA zeroing remains distinct from physical/acoustic erasure. Implementing and qualifying that actual codec contract, actual input/capture/play observations, device scheduling/heap/stress and live-provider/recovery acceptance are still required.
