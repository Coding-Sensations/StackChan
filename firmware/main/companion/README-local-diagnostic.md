# Opt-in local cold retirement diagnostic

This is a separate diagnostic startup, not a companion mode or a voice permission issuer. Production startup excludes `muse_local_diagnostic.cc`; the normal `muse-ram-reference` preset explicitly sets `STACKCHAN_MUSE_LOCAL_DIAGNOSTIC=OFF`. The opt-in `muse-cold-diagnostic` preset sets it ON, uses its own build/configuration directory, and refuses implicit `sdkconfig.defaults.local` overlays before loading them. Main source/profile guards are hash-pinned, including the diagnostic CMake policy.

The diagnostic requires the StackChan CoreS3 board, Muse+voice code and RAM-only selection. It rejects remembered routes, wireless/USB provisioning, local portraits and configured companion trust. Its Settings implementation is no-storage: reads return defaults, writes/erase are no-ops, and diagnostic startup never calls NVS initialization. Existing settings are not migrated or erased. The ordinary build retains its original settings and startup path.

## What starts and what waits

Boot prepares the existing board power/display/touch path and de-energizes motor/laser IO, then shows one 320x240 diagnostic panel. It skips SD mounting, RTC/network/USB/provisioning/normal launcher startup and never calls the normal audio constructor; the board's ordinary GetAudioCodec returns null in this build. Display/power bootstrap still changes normal peripheral rails/reset/backlight registers and polls the touch controller. This is not proof that an amplifier is powered off or acoustically silent before opt-in. The inherited Wi-Fi-board constructor may allocate its dormant timeout timer; it does not start that timer or a network connection. Dormant production/network libraries can remain in the complete registered link graph—this is a startup/call-path restriction, not a claim that every network symbol is absent.

The panel requires **Arm diagnostic**, then **Run once**, using the originally registered native pointer, exact visible target, press/release provenance and a 10-second bound. Cancel is available before Run. Direct synthetic clicks, foreign/stale/expired input, a closed view or moved/consumed grant cannot start SDK work. These are source/native-input checks, not cryptographic human or device attestation. A real LVGL pointer test with synthetic input remains offline software evidence.

The local action creates an opaque one-use grant for this cold check only. It grants no microphone, camera, speaker playback, provider session, native-host principal or remote receiver authority. The common MusePushToTalk enum is used solely as the existing exact custody tag, not as PTT permission. Production physical FlushOutput/PTT capability stays disabled.

## One synchronous original owner

A program-lifetime Owner acquires one exact common lease, looks up only the cold Core, and uses the board-owned I2C bus. It attempts cold initialization once, checked amplifier/stopped-DMA retirement once, then hardware/logical retirement only after complete actual receipts. It starts no worker; the operation returns synchronously outside the LVGL lock. No RX/ES7210, PCM handles, channel enable or audible stimulus is available. All I2S signal GPIOs remain unused. SDK internal clock/interrupt allocation is disclosed in the cold boundary documentation.

An admitted partial failure or exception revokes/retains original custody and resources; lost custody never acts on a successor. No reset, uncertain replay, deletion/recreation, new lease or automatic recovery follows. Closing a view before grant consumption revokes that grant; closing it after commitment cannot cancel/replay half an SDK operation. Native startup retains the owner for program lifetime even if UI/reporting fails. The final local report contains only fixed labels, numeric stage/status/register/byte evidence and immutable historical snapshots. It contains no token, identity, bus pointer, account, VM/chat/thread or exception text.

The attempt limit is volatile and per program lifetime. Power loss/panic/reset breaks continuity; a later boot returns to the idle opt-in screen. A reset is not a supported recovery proof, and unexpected reset must stop attended qualification rather than authorize another attempt.

`owner=complete` means the limited cold source sequence and custody retirement completed. It does not establish acoustic silence, active-playback discard, RX clock interaction, recovery boot, runtime heap/stress, microphone/voice/session continuity or any live provider acceptance. `retained-no-retry`, `custody-lost-no-action`, `audio-busy-no-action` and `local-optin-rejected` are not successful driver qualification. Initialization stage/fault numbers are the typed MuseColdStage/MuseColdFault enums in cores3_audio_codec.h; raw nested quiesce evidence keeps its recorded phase/status.

## Build and later attendance

With an existing qualified ESP-IDF5.5.4 toolchain and pinned cached dependencies, configure the `muse-cold-diagnostic` CMake preset and build with one job in its separate directory. No command in this document installs firmware or opens a device. The retained offline artifact receipt must pin source/configuration/SDK/dependencies, image SHA256/size/slot fit, static memory and unqualified behavior. Normal and diagnostic binaries must not be confused. Games/Music and local portraits stay excluded in this preset.

A later attended proposal needs fresh device custody/identity/security/table/selector and current-image/rollback comparisons, then exact OTA0-only installation/verification approval preserving OTA1, NVS, selector, assets, bootloader and table. Do not infer current device state from historical receipts. Recovery-slot boot is still separately unqualified. Installation of this diagnostic temporarily replaces normal companion startup; restoring a pinned normal image is a separate exact action.

After separately approved boot, first observe the idle panel without touching Arm: no diagnostic should run. Then separately authorize one Arm/Run and inspect the scrollable local report. No microphone, recording, network, real token or playback is part of that check. Stop on any error, mismatch, unexpected sound/movement/network/reset or retained state; do not retry or select recovery. This no-stimulus cold check cannot qualify active playback/acoustics. Any later output stimulus, recording/measurement, recovery, RX or live-provider test needs its own source contract and attended authorization.
